# Scheduled report failure repair

Eleven consecutive scheduled runs failed between 2026-09-11 22:30 UTC and
2026-09-13 05:27 UTC. The first and latest logs both show GitHub rejecting
`history/facts.jsonl` above its 100 MiB file limit. Tests, collection, candidate
validation and package verification passed; `Push committed snapshot` failed.
The failure job then posted a fresh comment to issue 71 on each retry.

Evidence:
- First failure: https://github.com/ashtonships/solana-ecosystem-report/actions/runs/34654295828
- Latest inspected failure: https://github.com/ashtonships/solana-ecosystem-report/actions/runs/34740324615
- Failure issue: https://github.com/ashtonships/solana-ecosystem-report/issues/71

The committed ledger contains 104,381,104 bytes. A lossless gzip comparison
produces 6,961,561 bytes, with decompressed SHA-256
`cbb0df5a6bdc58dfba174c9f016e4d15a0f5b207a894bde66dd9e0c0b0124775`.

## Repair

The collector writes deterministic standard-library gzip. The first successful
new collection reads the legacy ledger, includes its full canonical history,
writes `history/facts.jsonl.gz`, and removes the redundant legacy file. This code
change itself does not rewrite any committed data. Subsequent collections keep
the compressed format. Publication verification still proves the exact logical
append over the source revision and checks physical file checksums. Both ledger
formats existing together, corrupt gzip, record conflicts, and compressed files
above 95 MiB fail closed. Compression provides substantial headroom; history
partitioning will be needed if the compressed ledger approaches that guard.

Code checks replay the existing snapshot at its recorded collection time so an
outage cannot prevent its own repair. Collection, bootstrap publication, package
verification and hosted smoke checks retain their live freshness rules.

Failure reporting opens an issue for a new incident. An unchanged failing job
and step produce no additional issue write; a different job or step updates the
existing issue. GitHub's account-level Actions notifications remain enabled.

## Release verification

Run the offline suite and committed-data verification before release. After
merging, verify the next update migrates the ledger, passes exact data and
package checks, pushes the snapshot, deploys Pages, and passes the hosted smoke
check. A passing code check alone does not establish production recovery.
